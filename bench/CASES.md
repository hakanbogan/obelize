# Benchmark case definitions

A **case** is a candidate from [`CANDIDATES.md`](CANDIDATES.md) that somebody
has read and given a hand-written answer key naming every legacy call site.
The data is `bench/cases.yaml`; its fields are defined in
[BENCHMARK.md](../docs/BENCHMARK.md#case-definition) and decided in
[ADR-041](../docs/adr/ADR-041-case-definitions-split.md).
What each case produced is in
[BENCHMARK_RESULTS.md](../docs/BENCHMARK_RESULTS.md#round-1).

## How the twenty were chosen

By a rule fixed before the first clone, `bench/cases.py` `chosen`: every
candidate with a Python test file, then every candidate drawn for a pack
surface, then each pack change's only witness, then one per pattern key not yet
taken, then a systematic sample of the rest. The split follows
[BENCHMARK.md](../docs/BENCHMARK.md#dev--holdout-split) (`bench/cases.py`
`split`). `tests/unit/test_cases.py` recomputes both.

## How the ground truth was written

By reading the repository at the pinned SHA before its scan record was opened,
which the disagreement table below checks.

The reviewer opens every file matching a token list, plus every dependency
manifest, and records them in `files_read`. The list goes beyond the SDK's own
spellings, because a file can reach the SDK through the project's own wrapper
module; every key was read under it (ADR-041 D11).

A row is `auto` where a reader can see the answer even if the scanner bails,
as on two `configure` calls in two functions: a pre-registered miss. A row is
`manual`, with its reason, where the correct edit also needs a line that is not
a call site: a safety-settings dict that must become a list, a response
subscripted like a dict, a model chosen at runtime between two names.

Key corrections, each recorded in the row's own `why`; no row is ever removed
because the scanner did not report it:

- From the disagreement table: eight rows added from two files under
  `Functions/` a truncated grep had hidden, and a `genai.get_file(...)` inside
  a `'''...'''` block removed.
- `RuntimeAI/silly-merchants-for-safe-hackathon`'s Poetry pin moved from
  `pyproject.toml:23` (the `google-cloud-aiplatform` range above it) to 24. A
  manifest row is outside the table, so the error analysis caught it; no
  published number moves
  ([ADR-044](../docs/adr/ADR-044-error-analysis.md)
  D6).

## What a case is not

It is not a result. Install commands were read from each repository's manifest
and reviewed before any round ran them. One that fails in a round errors its case; one that is
incomplete is corrected only with a dependency the repository itself declares
([ADR-043](../docs/adr/ADR-043-round-one-results.md)
D7), as `navamai/navamai` gained the `pytest-asyncio` its Poetry dev group
declares. A case with no test command installs nothing, since nothing imports
its dependencies.

## The ceiling, and what it does to Gate 4

A case with no test command caps at `patched_unverified` and stays a case
(ADR-041 D7). A Python test file, recorded as path evidence as in the `Tests`
column of [`CANDIDATES.md`](CANDIDATES.md), is not a usable command: four of the
eight cases with one have none. One's only Gemini test passes keyword arguments the constructor
rejects, one's `tests/` holds live API probes that assert nothing, one's
`Tests/` is a scratch directory that never touches the SDK, and one's two
`smoke_test.py` files build a Kivy window.

## The negative controls

Three repositories that must produce no migration, each drawn by its own dated
query and confirmed by a scan: already on `google.genai`, on
`vertexai.generative_models`, and on `vertexai.preview.generative_models`. The
fourth shape [BENCHMARK.md](../docs/BENCHMARK.md#negative-controls) names, the
SDK mentioned only in documentation, came back `no_eligible_result`: a
repository whose README names `google-generativeai` usually imports it too.

## Reproducing this

`bench/cases_collect.py draw` re-runs the dated draws and rewrites
`bench/cases_draws.yaml` and `bench/results/cases/scan.json`; it needs the `gh`
CLI authenticated, `git`, and an installed `obelize`.
`bench/cases_collect.py checkout owner/name` leaves one repository at its
pinned SHA in the gitignored `bench/work/cases/` for a reviewer.
`bench/cases.py` re-renders the block from `bench/cases.yaml` and the three
scan records; `--check` fails when it is stale. `tests/unit/test_cases.py`
recomputes the selection, the split, the pattern keys and the agreement table
from the corpus, the draws, the scan records and `pack.yaml`.

Draws are dated, not reproducible
([`CANDIDATES.md`](CANDIDATES.md#reproducing-this)); the answer keys are
readings of pinned SHAs and do not move.
