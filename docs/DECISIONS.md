# Decisions

Architecture decision records live in [`docs/adr/`](adr/), and this is their index. An ADR without a
row here does not count as a decision; `tests/unit/test_status_claims.py` fails on an ADR without a
row and on a row without an ADR.

## Decisions not yet promoted to an ADR

Settled and implemented, but too small for an ADR; one that is questioned gets one.

- No `obelize inspect`: `obelize scan --pack` already shows what a pack matches.
- The console script is `obelize.cli:main`, not the Typer app, so argv handling, exit codes and lazy
  imports stay in obelize's hands.
- The version is single-sourced from `src/obelize/__init__.py` via `[tool.hatch.version]`;
  `obelize --version`, the wheel and the release tag check all read it.
- Development tools are a PEP 735 dependency group (`[dependency-groups].dev`), never an extra, which
  PyPI would publish as installable; a unit test enforces it.

## How to add a decision

Name the file `docs/adr/ADR-NNN-<slug>.md` with the next number and a slug of at most five words,
and give it the same three headings every ADR here uses: `# ADR-NNN: <title>` (the title also at
most five words), `## Status`, `## Decision` and `## Consequences`. Set the status to `Accepted`,
and add its row here in the same pull request. An ADR states the current decision and git keeps
its history: an amendment updates the amended ADR, whose status and row name the amending one, and
a superseded ADR is deleted with its row.
